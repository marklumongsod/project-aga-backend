# New Assessment Center Model

Estimates a **new or planned assessment center’s first 12 months**:

- chance of getting any candidates
- expected candidates in the first year
- expected candidates for each month 1–12

The model is the Team C artifact in `New_Center_Model/`. It runs as a **separate internal Python service**;
NestJS remains the only public backend and never loads the raw data or LightGBM/XGBoost.

This is **not** the monthly forecast. Use it only for a planned center, or a center accredited in the last 12 months
with no candidates yet. Once a center has assessment history, the monthly forecast takes over.

---

## 1. Architecture

```text
NestJS API (auth, role scoping, validation, mapping)
        |
        | POST /api/v1/new-centers/predict
        v
New Center Model service (FastAPI, internal)
  - InputBuilder loaded once (~1.2 GB)
  - XGBoost count model + LightGBM chance model
  - raw TESDA data mounted read-only
        |
        v
prediction JSON: chance, first year, 12 monthly rows
        |
        v
NestJS stores new_center_predictions and returns the result
```

The raw data and the model artifact stay private. The API image does not contain Python or the raw CSVs.

## 2. Inputs and outputs

Required input:

```json
{
  "province_id": 37,
  "qual_ids": [425, 142],
  "accreditation_month": "2026-11"
}
```

Optional: `city_id`, `school_ids`, `center_type`, `center_class`, `latitude`, `longitude`, `name`.

The Python service looks up the local situation from the raw data: learners in training, competitors, province market,
school learners, qualification details.

Output per center:

```json
{
  "chance_any_candidates": 0.293,
  "first_year_expected_real": 94,
  "monthly": [
    { "month_since_accreditation": 1, "target_month": "2026-09", "expected_real": 1.2 }
  ]
}
```

`*_real` is the full-population estimate (sample ÷ 0.2). The API shows `*_real` only.

The model was validated against `example_centers.json`: **29% chance, 94 first-year candidates**.

## 3. Backend ↔ raw T2MIS mapping

The model uses raw IDs; the API uses PSGC/qualification keys.

| Backend | Raw | File |
|---|---|---|
| province PSGC | `ProvinceId` | `docs/new-centers/province_map.csv` |
| qualification key/name | `QualId` | `docs/new-centers/qualification_map.csv` |

Generated by:

```bash
npm run new-center:map -- --data-dir /path/to/Data
```

Current map: **88 provinces**, **384 qualifications**.

Rules:

- Province names are matched to the raw `Province` sheet, with aliases for renamed/split areas.
- Historical BARMM duplicates use the current raw ID: Basilan 84, Lanao del Sur 89, Sulu 90, Tawi-Tawi 91,
  Maguindanao del Norte 92, Maguindanao del Sur 93.
- NCR districts use the raw TESDA district with the most centers: Manila 39, Second 88, Third 74, Fourth 76.
- Special Geographic Area maps to Maguindanao del Sur (nearest raw province).
- Qualifications use `QualificationTitle` + `LevelId` (Roman numeral), normalized with the same
  `qualificationKey()` as the dashboard (`Cookery NC II` and `Cookery II` are one).
- `city_id` is **not wired yet**. `cityKey` is accepted but not sent to the model; province + pin are used. A full
  `CityId` export from the data team is needed for city-level accuracy.
- `school_ids`, `center_type`, `center_class` are optional and currently not filled by the API.

## 4. Model service

Code: `New_Center_Model/service.py`
Image: `New_Center_Model/Dockerfile`

Environment:

| Variable | Meaning |
|---|---|
| `NEW_CENTER_DATA_DIR` | Raw data folder (10 CSVs + `Qualification.xlsx`) |
| `NEW_CENTER_LAST_MONTH` | Last complete month of the raw data, `YYYY-MM` |
| `NEW_CENTER_MODEL_DIR` | Model artifact folder; default `/app/models` |

Endpoints:

- `GET /health`
- `GET /meta` — last month, latest allowed accreditation month, model version, accuracy
- `POST /predict` — one or many centers
- `POST /reload` — reload after a new monthly export

Build and run:

```bash
docker build -t aga-new-center-model New_Center_Model

docker run -d --name aga-new-center-model \
  -p 127.0.0.1:8010:8010 \
  -v /path/to/private/Data:/data:ro \
  -e NEW_CENTER_LAST_MONTH=2026-10 \
  aga-new-center-model
```

Or with the Compose profile:

```bash
NEW_CENTER_DATA_PATH=/path/to/private/Data \
  docker compose --profile new-center up -d --build new-center-model
```

The Compose API reaches it at `http://new-center-model:8010`. For host `npm run start:dev`, use
`NEW_CENTER_MODEL_URL=http://localhost:8010` and publish the port as above.

Never publish this port publicly: the raw data contains learner IDs. The API should reach it on a private network.

Local validation:

```text
lastMonth: 2026-10
latest accreditation month: 2026-11
modelVersion: new-center-a3aae93e98af
example: chance 0.293, first year 94
```

## 5. API

### `GET /api/v1/new-centers/meta`

```json
{
  "lastMonth": "2026-10",
  "latestAccreditationMonth": "2026-11",
  "modelVersion": "new-center-a3aae93e98af",
  "sampleRate": 0.2,
  "trainedOn": "1228 new centers accredited January 2023 - September 2025",
  "testAccuracy": { "first_year_wape": 119.5, "bias_%": 27.5 },
  "versions": { "python": "3.13.7", "xgboost": "3.0.5", "lightgbm": "4.7.0" },
  "loadSeconds": 8.1
}
```

The frontend should use `latestAccreditationMonth` as the maximum month in the picker.

### `POST /api/v1/new-centers/predict`

Body:

```json
{
  "name": "Planned center A",
  "lat": 10.6765,
  "lon": 122.9509,
  "provincePsgc": "0604500000",
  "qualificationKeys": ["cookery ii", "bread and pastry production ii"],
  "accreditationMonth": "2026-11",
  "centerType": 2,
  "centerClass": 1
}
```

Validation:

- the province exists and the pin is inside it
- CO / RO / PO scope
- qualifications exist in the mapping
- `accreditationMonth` is at most `latestAccreditationMonth`

Response:

```json
{
  "id": "5e446705-18c8-45b4-8278-fb0304235f5d",
  "modelVersion": "new-center-a3aae93e98af",
  "lastMonth": "2026-10",
  "latestAccreditationMonth": "2026-11",
  "chanceAnyCandidates": 0.169,
  "firstYearExpected": 208,
  "monthly": [
    { "month": 1, "targetMonth": "2026-11", "expected": 2.8 }
  ],
  "accuracy": { "first_year_wape": 119.5, "bias_%": 27.5 }
}
```

`id` is the stored `new_center_predictions` row. The same input can be scored by another model version later and
compared by `model_version`.

## 6. When to use which model

| Center state | Model |
|---|---|
| Planned / not yet accredited | New Center Model |
| Accredited in the last 12 months, no candidates yet | New Center Model |
| Has had candidates in the last 12 months | Monthly forecast |

The monthly forecast integration is in the same branch (`/api/v1/forecasts`). It uses different tables
(`forecast_runs` / `forecast_values`) and a monthly batch import.

---

## 7. Accuracy and presentation

From the model’s test period (363 centers accredited January–September 2025):

| Measure | Value |
|---|---:|
| First-year error (WAPE) | 120% |
| Bias | +28% (forecasts too high) |
| Province totals error | 68% |
| Chance ranking (0–1) | 0.56 |

Use it to compare sites or qualification choices and to add up expected volume. Do not present it as an exact number.
About 4 in 10 new centers got no candidates in their first year; most start around month 3–4.

---

## 8. Data protection

- `New_Center_Model/Data/` is gitignored and excluded from the API image.
- The raw data contains learner IDs; keep it in a private, encrypted location with read-only access for the service.
- The output contains only IDs and numbers.
- The API image copies only `docs/new-centers/*.csv` (names and IDs, no learner data).
